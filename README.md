# Feature Impact & Product Analytics Case Study

**Read [`CASE_STUDY.md`](CASE_STUDY.md) — that's the actual deliverable.** This README is
just the project index.

A product analytics case study on one real, evidenced food-delivery friction point (ETA
volatility causing order abandonment), proposing a hypothetical feature (the "Delivery-Time
Confidence Indicator") and simulating — with real statistical rigor — an experiment and
post-launch result to evaluate it.

**The critical distinction, upheld throughout every file in this project:** the problem
evidence is real (a real Kaggle dataset + independently-verified real public reviews); the
feature, experiment, and results are explicitly hypothetical/simulated. Never confuse the
two — `CASE_STUDY.md` labels every section accordingly.

## Project structure

```
feature-impact-case-study/
├── README.md              <- this file
├── CASE_STUDY.md           <- THE DELIVERABLE: full case study, real vs. simulated labeled throughout
├── REAL_FEEDBACK_LOG.md    <- honest status: real human feedback is PENDING, not fabricated — see that file
├── requirements.txt
├── python/
│   └── power_and_simulation.py   <- power analysis + simulated post-launch A/B result (same
│                                     statistical rigor as the real A/B test in food-delivery-analytics)
└── output/tables/          <- the simulated results as CSV (power_analysis, primary_metric_result,
                                secondary_metrics, guardrail_metrics)
```

## How to run it

```bash
pip install -r requirements.txt
python python/power_and_simulation.py
```

This regenerates the power analysis and the simulated post-launch results referenced in
`CASE_STUDY.md`'s "Experiment Design" and "Post-Launch Analysis" sections. The random seed
is fixed, so the numbers reproduce exactly.

## What's real here vs. not (short version — full detail in `CASE_STUDY.md`)

- **Real:** the delivery-delay frequency/magnitude data (reused from the real Kaggle
  dataset analyzed in the sibling `food-delivery-analytics` project) and independently
  verified real public review evidence (Trustpilot, a corroborated 2022 regulatory-action
  news story).
- **Simulated/hypothetical:** the proposed feature, the experiment design and its input
  assumptions, and every post-launch number — all generated by `python/power_and_simulation.py`
  using real statistical methods (two-proportion z-tests, power analysis) applied to
  simulated, not real, data.
- **Pending, not fabricated:** real human feedback on the case study — see
  `REAL_FEEDBACK_LOG.md` for exactly what's needed to complete this honestly.
